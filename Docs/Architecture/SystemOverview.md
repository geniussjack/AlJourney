# Архитектура проекта AlJourney

## Обзор архитектуры
AlJourney использует компонентно-ориентированную архитектуру на базе движка **Godot 4**. Основные системы реализованы в виде **Singleton-менеджеров**, которые глобально доступны из любой точки игры через свойство `Instance`.

## Основные паттерны проектирования
1. **Singleton (Одиночка)** — используется для всех корневых менеджеров (`GameStateManager`, `AudioManager`, `SaveSystem` и т.д.).
2. **Data-Driven Design (Управление на основе данных)** — вся информация о предметах и способностях вынесена в статические классы-базы данных (`EquipmentDatabase`, `AbilityDatabase`). Это позволяет легко балансировать игру и добавлять новый контент без изменения логики кода.
3. **Dependency Inversion (Инверсия зависимостей)** — все ключевые менеджеры реализуют строгие интерфейсы (например, `IGameStateManager`, `IInventoryManager`). Это снижает связность кода и улучшает тестируемость.

## Взаимодействие систем
* **GameStateManager** — ядро игры, отслеживающее текущую фазу (главное меню, бой, магазин) и глобальные параметры (монеты, волны).
* **SceneManager** — управляет переходами между сценами, опираясь на состояния из `GameStateManager`.
* **BattleManager** — изолированная система, которая инициализируется только во время сцены боя. Она берет на себя оркестрацию ходов игрока и врагов.
* **GridManager** — независимый компонент Match-3. Сообщает `BattleManager` о найденных совпадениях через события (Action/Delegate).

## Дерево узлов (Node Tree)
В Godot все менеджеры добавлены в `AutoLoad` (Глобальные переменные), что гарантирует их инициализацию при старте приложения до загрузки первой сцены.
